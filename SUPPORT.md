# Getting help

| You have | Go to |
| --- | --- |
| A question, an idea or something to show | [Discussions](https://github.com/stepan4002/plumbcheck/discussions) |
| A reproducible bug | [New bug report](https://github.com/stepan4002/plumbcheck/issues/new?template=bug_report.yml) |
| A feature request | [New feature request](https://github.com/stepan4002/plumbcheck/issues/new?template=feature_request.yml) |
| A security vulnerability | Email, never a public issue: see [SECURITY.md](SECURITY.md) |

## Response times

PlumbCheck is maintained by a small team. We aim to:

- reply to every new issue and discussion within **one working day** (Monday to Friday, CET), even if the first reply is only a triage label or a question;
- label confirmed bugs, and say whether a fix is planned, within **three working days**;
- review pull requests within **three working days**.

These are goals, not guarantees. If something has waited longer, a polite ping on the thread is welcome.

## Before opening an issue

- Check [open issues](https://github.com/stepan4002/plumbcheck/issues) and the docs in [`docs/`](docs/).
- Use synthetic data in reproductions. Never paste API keys, personal data or private agent traces.
