# First-use acceptance pass

Target preview.5 application source: `4a829a5635f9d2d4fb4125d57c4f496e968018eb`. Record the exact commit/build, environment and pass/fail/not-run for each item. Automated baseline: 208 core tests, seven official MCP checks and one packed TypeScript consumer check. Native visual and physical-device checks are additional evidence.

Use synthetic data and a new disposable workspace. Source Studio accepts an isolated `PLUMBCHECK_HOME`; open its private launch link. Do not overwrite a real user's workspace. Do not share launch fragments, capabilities, API keys, pairing codes, credential files or workspace databases. No paid providers, real business tools, installs beyond the locked test dependencies, security changes, publishing, pushes or merges are required by this pass.

1. **Fresh start:** open Workspace with no projects. The scenario builder should be expanded. The order template should be editable without opening a JSON editor. Saving the untouched first template should create one project without an unsaved-example replacement prompt.
2. **Meaningful failure and correction:** change the planned order ID to `WRONG-ORDER`, preserving expected `ORD-1042`. Save, run offline, and inspect `ARGUMENT_MISMATCH` plus expected/actual values. Correct the planned ID, save with the same builder project still open, and run again. Expect failure → pass for one case, one project and successive revisions. Comparing the two runs must not show removed cases.
3. **Typed/custom fields:** build a ticket lookup and try nested text, number and boolean fields. Duplicate/overlapping paths, reserved prototype paths, invalid numbers/booleans and an empty argument/response group must fail before saving. A normal nested field should appear in exported JSON at the expected path.
4. **Preserve work:** edit the Contract/name/task, then try replacing it through the builder or opening another project. Cancel must preserve it. Cancel New project and check its explicit cancellation notice. If slow I/O can be introduced safely, edit while a project opens or saves; newer edits must remain and older responses must not replace newer choices. Remove any dialog auto-accept handlers before these checks.
5. **Feedback recovery:** Export scenarios, then import a malformed file and malformed paste. The prior workspace export success must disappear. Save/run successfully afterward: the previous import error must disappear. Invalid imports must preserve the draft and current evidence.
6. **Ollama setup:** if an existing local server is available, choose Find Ollama, select an actually returned model ID and save. Model-run mode should select that connection, also after later builder saves, but leave consent unchecked. Manually switching back to the planned-call check must survive refreshes. A real model run must require separate consent. If no server/model is available, verify actionable error feedback and record the actual model run as not run; do not install a model for this pass. Changing a provider/address during discovery must not populate stale model IDs.
7. **Evidence and restart:** export/open the actual result, restart and reopen the saved project/history. Imported reports remain read-only/not rerun. Initial Results must identify their built-in example. The legacy smaller passing example has two cases and must not be confused with unchanged six-case coverage.
8. **Android:** use the same form workflow in the installed APK when an actual device/emulator is available. Verify offline fail/fix, cancellation, saved-project/evidence recovery and file pickers. A browser/DOM run alone does not verify the native host. Physical-phone Ollama and HTTPS sync require their separate acceptance passes.

Return exact reproduction steps for each unexpected result, expected/actual behaviour, redacted screenshots and command logs. State untested environments clearly, and disclose automation/dialog-handler caveats. Inspect any evidence bundle for secrets before sharing it. Stop disposable Studio/relay services at the end.
