## Summary
When done, a contract can check an LLM's prose/JSON final answer (`expect.outputChecks`), accept LLM-varied arguments through
explicit `$plumb` matchers, and declare real tool descriptions/schemas (`tools`) that models and MCP clients see. The no-JSON
builder gains "must not" templates (unapproved send, forbidden delete, injected instruction) plus a "final answer must contain"
field, and once a model connection exists the Workspace defaults to a real model run. `npm run test:probe` reruns a committed
six-scenario live suite against any local (loopback) or explicitly opted-in cloud model and reports whether PlumbCheck caught
each case. Modes that cannot evaluate output checks say so instead of passing silently. Contract version stays 1 (additive fields).

## Approach
- **Output checks:** `expect.outputChecks: [{ path?, equals? | contains? | notContains? | matches?, ignoreCase? }]` (not overloading `expect.output`). Valid in planned and agent contracts; evaluated only where agent/model output exists. Elsewhere the case records `skippedOutputChecks: n`, surfaced in CLI, HTML/workbench, Android, MCP audit — never a silent pass. Code `OUTPUT_ASSERTION`.
- **Matchers:** reserved key `$plumb` in fixture `arguments` only (never in `calls`, never in `result`, never as the arguments root): `any`, `contains`, `matches`, `oneOf`, `range`, `literal` (escape). `literal.value` and `oneOf.values` are opaque JSON in every walker.
- **Regex safety:** ≤200 chars; reject backrefs (`\1`–`\9`, `\k<`) and a quantified group containing a quantifier; compiled with the exact runtime flags (`''` or `'i'`). Values longer than 20,000 chars are *not* truncated: a `matches` check/matcher on them fails ("too long to check with a pattern"). `contains`/`notContains`/`equals` have no cap (linear).
- **Tools:** suite `tools: { [name]: { description?, inputSchema? } }`; `inputSchema` root `type:"object"`, `properties` object if present, `required` string array if present, ≤20 KB JSON, depth ≤32. Declared schemas are enforced by the provider/SDK (documented).
- **Shared runtime:** new self-contained `src/matchers.js` (`createMatchers()`, no imports) for replay/evaluate/mcp-schema; validation inlined in `contract.js`.
- Rejected alternatives: JSON-Schema argument validation (heavy, leaks expected values); LLM-judge grading (nondeterministic, spends credits); probe-specific contract keys (strict validator) — expected outcomes live in the probe script.

## Implementation steps
1. **`src/matchers.js` (new)** — `export function createMatchers()` → `{ isMatcher, matchValue, diffExpected, checkOutput, regexp }`.
   - `isMatcher(v)`: plain object with own `$plumb`.
   - `matchValue(expected, actual)`: matcher → kind logic (`any` true; `contains` requires string actual, `includes` w/ optional lowercase; `matches` requires string ≤20,000 then `regexp(pattern, ignoreCase).test`; `oneOf` deep-JSON-equals any of `values` (opaque); `range` requires finite number actual within min/max; `literal` deep-JSON-equals `value` opaquely). Arrays: same length, element-wise. Plain objects: identical own key sets, recurse. Primitives: strict equality (NaN impossible in JSON). No coercion anywhere.
   - `diffExpected(expected, actual)`: copy of expected where *satisfied* matcher leaves are replaced by the actual value (used only for the diff view).
   - `checkOutput(check, output)` → `{ passed, found, value, reason? }`: path '' / absent = whole output; dotted own-property path into objects/arrays; on string output a non-empty path → not found. Operators: `equals` deep JSON equality; `contains`/`notContains` on strings directly, other found values on `JSON.stringify(value)`; `matches` on strings only (non-string or >20,000 chars → fail with reason). `notContains` on missing output/path **fails** (`actualMissing`). `ignoreCase` lowercases both sides / uses `i`.
2. **`src/contract.js`** — inline helpers (no imports):
   - `pattern(value, label)`: string 1–200, reject `/\\[1-9]|\\k</`, reject nested quantifier `/\((?:[^()\\]|\\.)*[+*}](?:[^()\\]|\\.)*\)\s*[+*{?]/`, then `new RegExp(value, 'i')` and `new RegExp(value)` compile inside try → `Invalid suite: … pattern`.
   - `matcherTree(value, label, depth, root)`: depth ≤64; at root, value must be a plain object and must not itself be a matcher; for objects with own `$plumb` validate exact keys per kind — any `{}`; contains `{value: string ≤4000, ignoreCase?: boolean}`; matches `{pattern, ignoreCase?}`; oneOf `{values: array 1–50}` (opaque, not walked); range `{min?, max?}` finite numbers, ≥1 present, min ≤ max; literal `{value}` (opaque); recurse into other objects/arrays.
   - `call(value, label, fixture)`: fixtures → `matcherTree(value.arguments, …, root=true)`; planned calls → reject any own `$plumb` anywhere in arguments (walk) with "matchers are only allowed in fixture arguments". `result` untouched.
   - Suite key `tools` (L29): object ≤200 entries; names 1–128 chars; entry keys `['description','inputSchema']`; description string ≤2000; inputSchema object, `type === 'object'`, `properties` object if own, `required` array of strings if own, `JSON.stringify` length ≤20,000, depth ≤32.

## Risks & mitigations
- **ReDoS (1, 2):** length cap, backref + nested-quantifier rejection, 20k value refusal; heuristic not a proof → SECURITY.md.
- **Fail-open checks (5, 6):** skipped checks are recorded and displayed; over-length and missing values fail.
- **Discovery leak (7):** matcher schemas carry no values; tests assert literals absent.
- **Serialized factories (2, 4, 11, 12, 13):** no imports/closures; `test/artifacts.test.js`, `test/diff.test.js` rebuild via `new Function`.
- **UI pins (12, 13):** template button uses `[data-template-kind]`; consent untouched; touched flag only from real events.
- **Probe nondeterminism/spend (15):** `inconclusive` ≠ `missed`; cloud needs key + ALLOW_SPEND; per-case budgets.
